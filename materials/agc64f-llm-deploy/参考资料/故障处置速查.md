# 故障处置 & 口径背景（六实验）

`SIX_BENCHMARK_SOP.md` 的配套文档：指令在 SOP，这里放排查、背景和日志位置。
硬性安全约束以 `AGENTS.md` 为准。

## 1. 故障处置

| 现象 | 处置 |
| --- | --- |
| `CUDA error(719) unspecified launch failure` | 立即停止，不重试、不重启 Docker/containerd，保留日志并报告 |
| 容器停止无 exit event / `ttrpc closed` | 同上；只清理本轮明确创建的容器 |
| `lspci` 出现 `rev ff`、config space 全 `ff`、`D3cold` 无法恢复 | 立即停手，收集日志报告，不做任何 VFIO/PCI 操作 |
| `not ready 65535ms after FLR`、QEMU `ich9_route_intx_pin_to_irq` assertion | 同上 |
| `OpenEncodeSessionEx failed: incompatible client key (21)` | 用了未打补丁的镜像；改用 `video-in-micro:ffmpeg-nv-stress-v4-patched` |
| 汇总出现 `GPU telemetry coverage: 0/32` | 遥测代码没找到 smi；本机只有 `dx-smi`，确认 `stress/*.py` 用的是 `nvidia-smi or dx-smi` |
| 部署时报 `create container timeout: <id>` | Kata 建容器超时，通常是刚清理过一批 VM、资源未回收；只 `docker rm -f` 卡住的那个名字（如 `g1`），确认无残留 `qemu-system`/`containerd-shim-kata` 后重试一次；连续失败则停手报告 |
| ASR 启动后卡死不退出（日志停在 `funasr version: …`，32 个 worker 全 0% CPU/GPU） | FunASR `AutoModel` 初始化会向 `pypi.org` 发**无超时**的版本检查请求，无外网时永久挂起。已在 `asr-test/configs/asr_paraformer_large*.yaml` 的 `pipeline_kwargs` 设 `disable_update: true`，**不要删** |
| Kata guest 吞吐远低于 Docker（如 OCR 单卡个位数 images/s） | `docker exec <容器> nproc` 看核数；Kata 默认 `default_vcpus = 1`，入口必须显式传 `--cpus`（OCR 用 `OCR64_KATA_CPUS`，默认 **24**；视频解码默认 48、编码默认 24） |

## 2. 容器日志看哪里（重要）

六个实验的容器**都用 `--entrypoint /bin/bash … -lc "sleep infinity"` 常驻**，PID 1 不产出任何
stdout，所以 **`docker logs` 对这些容器恒为空**（json 日志文件 0 字节）。这不是故障，是设计：
容器先常驻，才能做"Kata 全部 ready → Docker smoke → 逐卡预热 → 共同窗口"的准入控制。
负载由 `docker exec` 拉起，输出只回到发起它的终端。

日志在这三个地方：

1. 跑入口脚本的那个终端
2. `ocr/outputs/v1/<run-id>/coordinator.log`、`<unit>.launcher.log`、`<unit>/worker-N.log`
3. 容器内实时状态：`docker exec g1 ps -ef`、`docker exec g1 du -sh /dev/shm/ocr-v1/corpus`

## 3. 判定口径背景

- **OCR 64 卡**：`det_batch=8` / `rec_batch=64`，60s 固定窗口，预编译 tensor 语料（窗口内无磁盘 I/O）。
  脚本内部顺序固定为**先 Kata（g1→g4 逐组 ready）再 Docker（d1、d2）**，全部 ready 后才共同进入
  正式窗口 —— 这是 CUDA-719 事故后的安全准入顺序，**不要改成先起 Docker**。
- **YOLO 32 卡**：fixed-window 60s、1000 张 COCO、`ram_loop_images=64`、`queue_depth=16`。
  `YOLO_IO_BINDING=1`（默认）把循环图片常驻显存，窗口内不做 H2D/D2H 拷贝；不可用时自动退回
  `session.run` 并打印 `[WARN]`。定位过程见 `docs/YOLO性能问题定位_20260919.md`。
- **视频编码**：只保留最优格式 H.264（`VIDEO_KATA_STRESS_CODECS=h264,hevc` 可加 HEVC）。
  认证档位 `Certified streams/GPU: 10`，整机 320 路。
- **视频解码**：认证档位 40 路/卡、整机 1280 路。历史最优 32502.5 FPS 是 2026-07 用
  「每路一个 ffmpeg 进程 + `-re` 定速」的**旧实现**测的；当前实现（2026-08-14 起）改为
  「每 GPU 一个 ffmpeg 进程批量喂 40 路」，不是同一条代码路径，因此以**会话容量**为判据，FPS 仅作记录。
- **ASR / TTS**：ASR = Paraformer-Large batch 64，1000 wav × 8 轮 = 8000；TTS = Qwen3-TTS-1.7B，
  batch 30 / `max_new_tokens=128`，200 条 × 32 轮 = 6400。
